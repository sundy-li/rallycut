# 活动结束确认修正（perspective-activity-v2）

## 问题与证据

第二批反馈指出同一斜视素材的四个候选结束太早：153.553、162.396、170.837、184.317 秒。另补充 0–4 秒尚未开始，不应算回合。原片、标注和时间轴只读检查，未自动改成“已解决”。项目已有人工时间轴，复核结果必须另存新项目，不能静默替换。

四个候选的结束原因都是 `ball_settled`，不是几何触网事件。v1 的错误：

1. 等待 0.6 秒窗口和 0.3 秒确认后，仍回溯到慢速窗口第一帧作为结束，截掉约 0.87 秒末拍。
2. 待确认期间只用完整跨桌飞行撤销结束。正常击球的局部加速尚未完成跨桌时，也可能被结束；其中一个真实回合被切成两条。

开头只有不足以成回合的短视觉碎片；旧音频融合用 3 个附近观测点，就将附近击球声扩成候选。单纯检测到球不证明回合已经开始。

## 规则修正

- `vision/rally_activity.py`：结束只落在真实观测的确认时刻，不回溯慢速窗口开头。确认期间在短 PTS 窗口内发现持续水平位移与速度恢复，则撤销待结束；无需等完整跨桌，也不依赖名义 FPS。孤立位置尖峰不算恢复，纯竖直坠落不能冒充恢复对打。
- 仍保留等待与低位/低速证据要求；不是单纯把所有 gap 加长。旧回送、捡球、再次发球和短发球失败回归必须保留。
- `vision/audio_features.py`：保留并行开发的 `confirm` 分支（仅标记已有候选）。比较用 `legacy` 分支也不能用静止点或慢速准备片段支撑音频新建回合：需已有合格视觉候选，或单条连贯轨迹具有足够运动证据。不能拿不同轨迹之间的位置跳变伪造飞行。
- 不硬编码文件名、时间点或“跳过开头 N 秒”。同样的静止/准备音频反例在平移 100 秒后仍拒绝；无几何仍检测与跟踪，不能以找桌成功作为检测门槛。
- 版本为 `full-frame-v3` / `perspective-activity-v2`。这些仍是活动候选边界，不能宣称已判断下网/出界；剪辑 pre/post-roll 与识别边界分开。
