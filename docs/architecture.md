# 架构 / ADR 001

状态：已实施软件闭环与 BlurBall 专用预训练球检测（MPS / CPU）；回合规则与准确率验收仍未完成。

## 决策

1. Wails v2 + React / TypeScript，Go 方法通过 Wails 绑定调用；剪辑任务使用 `job:update`，首次环境准备单独使用 `setup:progress`。
2. Go 单体核心；同时只允许一个分析或导出任务。任务运行时禁止项目切换和编辑，避免结果写入错误项目。
3. Python 3.12 + OpenCV / NumPy / 可选 PyTorch 子进程，单请求 / 单进程，以换行 JSON 通信；Go 校验每条事件。取消通过 `CommandContext` 终止子进程，必须 `Wait` 回收，不使用 shell 拼接。
4. FFprobe 探测源媒体，FFmpeg 转码剪辑。使用原片显示时间轴秒数，不使用帧数 / 假定 FPS。真实检测输出解码 PTS 和短轨迹，JSON 结果上限 32 MiB；有音频时 Go 先提取临时 PCM，Python 分块计算瞬态，不生成仅有声音证据的回合。
5. JSON 文件原子替换，权限 0600，数据目录 0700。人工时间轴与模型候选分离；持久化完成后再更新内存中的人工编辑。
6. 缓存键包含源视频完整 SHA-256、协议、模型版本、固定权重 SHA-256 及内嵌 Python / 模型配置源码摘要。任何算法代码 / 权重变化隔离旧结果；若增加可变推理参数也必须纳入缓存键。
7. worker、视觉 / 声音 / 网络适配器和带 MIT notices 的 BlurBall 原始网络定义通过 Go embed 打包；权重不嵌入。另行显式安装、固定大小和摘要校验、weights_only 安全加载、严格 state_dict；缺失 / 错误不能自动退回旧规则。
8. 禁止把未明确分发许可的权重打包发布。用户请求的官方公开权重本地验证与对外再分发分开管理；当前权重的独立条款仍待确认。详见 licenses.md。

## 整帧检测与可选几何

默认 `table_mode=optional`，正常解码直接进入模型，不前置标定或跳搜，不按桌面 ROI 过滤检测/跟踪。可选几何随解码取得，缺失时不制造全画面伪桌面或几何死球事件。切镜以不可变逐帧快照传递，模型三帧输入、轨迹和回合均不跨镜头；几何只在可信时段有效。`off` 禁用辅助，`precalibrate` 显式请求旧搜索（失败仍继续检测）。空球桌结果在协议、保存和 UI 中合法。详见 [full-frame-detection.md](full-frame-detection.md)。

## 调用路径

```text
React → Wails backend.App → project / storage
                       ├→ jobs.Manager → analysis.Run → Python JSONL
                       └→ jobs.Manager → export.Run → FFmpeg / FFprobe
React ← job:update ← Go（原子保存任务状态）
<video> → /media/source?project=<id> → 活跃项目的唯一原片
```

媒体接口使用 `http.ServeContent`，支持 Range / HEAD。只允许当前项目 ID，不接受任意文件路径；不另起公开的 HTTP 服务。

## 导出策略

先对已选回合按起点排序，加前后缓冲、裁剪到视频边界、合并重叠范围。每段按所选格式重新编码为 H.264 或 HEVC / AAC，再 concat stream-copy；macOS 自动模式优先 `h264_videotoolbox` / `hevc_videotoolbox`，使用目标视频码率，不传 preset / CRF。硬件失败后整批改用 libx264 / libx265，不混拼不同编码器的片段。HEVC 加 `hvc1` 标签。继承旋转后的显示方向、偶数尺寸、方形像素、重置片段时间戳，并用音频异步重采样保持时间线。最终使用 FFprobe 检查视频有效、编码一致、时长误差和音轨存在性。导出设置独立保存在项目的 `export_settings` 中，旧项目缺省为 H.264 / auto。

输出在目标目录的临时工作区生成，完成并校验后使用同卷硬链接原子发布且不覆盖目标，随后清理临时文件。取消 / 失败时不会发布半成品。不保留源字幕、多音轨、HDR 元数据或多轨工程。

## 可靠性与边界

- 单任务上下文：分析 30 分钟、导出 4 小时；应用退出取消并回收子进程。
- 原始分析以整任务为缓存单元。协议或子进程失败时不写入半个结果。
- 已有人工修改的项目重跑分析，保留人工列表（包括空列表）。
- 程序异常结束后项目中 `running/cancelling` 状态恢复为 `interrupted`，用户手动重试。
- 导出前和分析前重新校验源哈希。处理期间请勿由外部程序改写源文件。
- 目前导出阶段进度为片段级，不是 FFmpeg 逐帧进度；首次全文件哈希期间 UI 显示等待。
- 未实现逐帧 checkpoint、撤销 / 重做、文件移动重关联、手工精确球桌标定、神经网络回合状态分类、逐回合准确率验收和自动恢复运行。已有专用神经网络球检测及显式权重安装 / 校验，但球桌标定和回合切分仍是规则。
- 应用启动先执行本地环境检测；缺少依赖时展示确认页，用户明确点击后才自动准备平台运行时。环境未就绪时，前后端门禁均不允许进入工作台，快捷键和原生菜单也不能绕过。自检通过才显示本地项目首页。详见 [first-run-setup.md](first-run-setup.md)。最近项目索引只保存路径与摘要。选择最近项目或“打开项目文件”时才校验项目与原片，成功后进入工作台。启动时仍可恢复上次项目对象供“继续当前项目”使用，但不会跳过项目选择页。项目使用独立时间戳名称和 `<项目名>-rallycut.json` 单文件格式；新建项目先命名、再选择视频。工作台可双击项目名重命名，元数据文件名、最近记录和 `last-project` 指针同步更新，但不会重命名或移动视频。删除项目只移除该元数据文件及最近记录，不删除任何视频或素材。
- 标准容器 / 编码测试不代表所有 VFR、旋转、长 GOP、特殊音轨已经验证。发布前需扩大测试矩阵并人工验收同步。
- 当前源码支持用户确认后下载应用私有依赖；不把权重打进安装包，不修改全局 PATH。`v0.1.0-alpha.3` 已纳入首次准备流程；Windows 使用安装时展开的预制 CPU 环境，Mac 首次确认后准备私有依赖，详见安装指南。Windows WebView2 的前置安装确认已中文化，依赖 Wails 默认原生引导器，不混入应用内进度。签名、公证、Windows / Intel Mac 无依赖真机与断网场景仍需验收。
