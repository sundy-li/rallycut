# 数据集与人工标注

状态：未收集真实视频；仓库内只有自动生成的合成测试素材，不是算法评估数据集。

## 收集清单

准备 10–20 段获得使用许可的比赛视频，覆盖：固定机位、远景、小球模糊、遮挡、多球干扰、光线变化、不同球桌、暂停和场外运动。记录来源 / 授权、SHA-256、编码、分辨率、帧率类型、旋转、是否含音频。素材不提交 Git。

以原始视频 / 比赛为单位划分 train / validation / test；同一场比赛不同片段不得跨集合，防止数据泄漏。模型调参只用 validation，test 冻结后不得参与调参。

## 标注格式

每个视频一个 JSON，示例见 `tests/fixtures/annotations.example.json`。所有边界以显示时间轴秒数记录，不依赖固定 FPS。默认回合起点为发球开始，终点为该分最后一次有效击球 / 明确死球；发生争议时在 notes 记录并复核。片头 / 回放 / 暂停不算回合。

`excitement` 使用 1–5 的人工等级；记录遮挡、相机运动等 tags。建议两人独立标注一部分样本，复核超过 0.5 秒的边界分歧。

## 回归集

每个漏检 / 误检 / 错误合并都应保存源哈希、时间范围、预期边界、算法 / 权重 / 配置版本。`tests/golden/` 放小型结果 JSON，不放未获授权视频。报告必须同时给出独立视频数、真实回合数和难场景分层结果。
