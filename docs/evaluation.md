# 回合准确率回测（私有标注库 + L0 检测缓存）

分析分三层：L0 检测（解码、切镜 / 可选几何、球模型、声音冲击，最慢）→ L1 跟踪（`visual.update_tracks`）→ L2 回合规则（`rally_*`、`play_area`）。绝大多数优化只改 L1 / L2，所以 L0 只新鲜推理一次并缓存，之后的回测在缓存上重放，全部标注视频几秒到几十秒。

## 标注库

放在仓库外（含用户私有视频的真值，不提交 Git、不上传），用 `RALLYCUT_LABELS_DIR` 指定：

```
rallycut-labels/
  dataset.json           videos[]: id、labels、file、role（dev / holdout）、view；video_root（默认 ..）
  videos/<id>.json       video 元数据、covered（已标注范围）、start_convention、rallies[]
  cache/<id>/<摘要>/     l0.json.gz、fresh.json、meta.json（重放一致性）
  baselines/<名>.json    保存的基线
  reports/               每次回测的 Markdown / JSON
```

回合字段：`start`、`end`（原片 PTS 秒），可选 `optional`（擦网重发 / 不确定：识别出或漏掉都不计）、`tag`（let / serve_fault / handover …）、`note`、`start_convention`。

## 打分口径（`vision/evaluation.py` `score_labels`）

- 只比较 `covered` 范围（候选中点在范围内）；范围外不计误报。
- 可选回合不计分；与它重叠过半的候选既不算对也不算误报。
- IoU≥0.5 一对一匹配；另报 IoU≥0.3。
- 起点口径：`serve_preparation`（从发球准备标）接受晚至 8 s 的起点；算法检到颠球（`start_reason=serve_prep`）的候选可比抛球口径的真值早至多 8 s。终点始终严格。
- 边界准 = 调整口径后起点、终点误差都 ≤1 s。

## L0 缓存

`headless.py analyze --dump-l0 <path>` 在新鲜推理时写出每个送入模型的帧的 PTS、镜头快照（含可选几何）、原始模型点，以及最终镜头状态、切镜、几何分段、声音冲击（gzip JSON，30 fps 的 50 分钟视频约 1–3 MB）。`detection_cache.replay` 把它按原顺序喂给 `neural_analysis.TrackingStage`——新鲜分析也用同一个类，所以未改代码时重放结果与新鲜推理逐项相同（单测 `test_l0_cache_replay_reproduces_the_fresh_result`；`eval cache` 对真实视频再核对一次，不一致的缓存不会被使用）。

缓存摘要覆盖：模型名、权重 SHA、设备、精度、batch、解码器、table_mode、是否有声音，以及 L0 源码（`pretrained`、`backends`、`video_decode`、`shot_boundary`、`table_locator`、`table_jump`、`net_geometry`、`audio_features`、`inference_pipeline`、BlurBall 网络与配置、`DetectionRun`、`visual.find_table`）。这些变了，缓存自动失效，需要重新 `eval cache`；不会静默用旧缓存。

| 改动 | 回测 |
|---|---|
| 回合规则、场外标记、跟踪 | `just eval run`（重放，秒级） |
| 模型 / 预处理 / 解码 / 精度 / 切镜 / 几何 | `just eval cache` 后再 `run`（新鲜推理，全部视频约 30 分钟） |

热力图不缓存（每帧 512×288，整场数十 GB）；峰值提取门槛等改动需要新鲜推理。

## 命令

```bash
export RALLYCUT_LABELS_DIR=~/Documents/生活/video/rallycut-labels   # 用户本机位置
just eval status                       # 视频、标注、缓存状态
just eval import <项目.json> --id <id> [--covered 0-430 --covered 1200-1800] [--view side]
                                       # 从 RallyCut 项目导入人工回合（manual-* 与 edited=true）
just eval cache                        # 缺缓存的视频做一次新鲜推理（默认 torch / MPS / FP32）
just eval run                          # 重放 + 打分 + 报告
just eval run --save-baseline v15      # 保存基线
just eval run --compare v15 --gate     # 与基线逐项对比；任一视频 F1 降 >0.02 或召回下降则失败
```

## 纪律

- 新标注的视频第一次打分原样记录，这是它的独立测试成绩；之后才决定 dev 或 holdout。
- dev 可看错误、调规则；holdout 只在发版前跑总分（报告默认隐藏其错误明细），不据此调参。
- 重放和新鲜推理是不同证据：报告注明来源；改 L0 相关代码后必须重新 `eval cache`。
- 候选数量、置信分数不是准确率；没有覆盖的场景（端线转播等）不因回测通过而宣称可用。

## 新视频接入流程

1. 用户在应用里人工标注（项目在 `~/Library/Application Support/RallyCut/projects/`）。
2. `just eval import <项目.json> --id <id> --view <机位>`；只标了部分时间就用 `--covered` 写明范围，范围外不计分（用户会之后再补标）。
3. `just eval cache --video <id>`：一次新鲜推理，写 L0 并核对“重放 = 新鲜推理”。
4. `just eval run --video <id>`：**这次结果就是该视频的独立成绩**，先原样报告给用户并把报告复制为 `reports/<id>-first-independent-<版本>.json`，再看错误、决定是否改规则。之后它就是 dev。
5. 对错误有疑问（擦网？递球？捡球？）直接列时间问用户，按回答改标注（`optional` / `tag` / `note`，改动保留 `original_*` 字段），不要猜。

## 标注口径（用户已确认，打分和规则都按此）

- **起点**：有颠球（台上或地上颠均算）就从颠球开始；看不到颠球就从发球（抛球）开始，两者都算对。颠球识别不到“也没事”，但要尽可能识别。旧数据里 fzd 0–430 s、0041、0043、0044、0045、he 按抛球标（`toss`），fzd 20:00–30:00 按发球准备标（`serve_preparation`）。
- **终点**：球死那一刻（落地、下网、出界后被接住）。捡球、把球回送 / 丢给发球员都不属于回合。
- **擦网重发（let）**：可算一个回合，也可不算 → `optional`。
- **发球失误**：算一个回合（即使只有发球）。
- **递球**（别人把球丢给发球员）：不是回合；识别出来算误报。
- **范围**：只在用户标注过的范围内比较；没标的部分以后补，不能当作“无回合”。
- **人工与机器**：重分析不覆盖人工回合；机器候选与人工回合重叠也保留，导出时由重叠对话框选用哪份（见 `AGENTS.md`）。

## 规则优化纪律

- 不用声音判断（邻桌球声）；不针对文件名 / 时间点 / 单个视频调参。
- 每个改动都在全部视频上跑 `just eval run --compare <基线> --gate`；只保留**不让任何视频变差**的改动。
- 参数做敏感性扫描，取结果不变的平台区，不取刚好卡过的点；把扫描结论写进对应规则文档。
- 被拒绝的尝试也写进文档（为什么不行），避免下次重复。
- 规则改动同步：`VERSION` / `implementation` 字符串、`models/manifest.json`、`skills/.../output-schema.md`、`AGENTS.md`、规则文档、单测（去掉规则时单测须失败）。
- 改完保存新基线 `just eval run --save-baseline v<N>`。

## 已拒绝的规则尝试

| 尝试 | 结果 | 原因 |
|---|---|---|
| 颠球一律把起点前移（早期版本） | 拒绝后改为“检到颠球才前移”（v4） | 早期标注按抛球，前移使 IoU 下降 |
| 统一前移 3 s 补发球准备 | 拒绝 | fzd 20–30 变好，但 0–7、0044、0045 明显变差；用导出“发球前保留秒数”解决 |
| 放宽颠球幅度 / 间隔 / 次数 | 拒绝 | fzd 最多多命中 2 个，0044 / 0045 出现假颠球起点 |
| “发球方附近一直有球就前延”起点 | 拒绝 | 业余视频变差 |
| 递球识别（单拍、落点即下一次发球处） | 拒绝；v8 的“孤立一拍”覆盖了 0045 01:37 | 删掉 0044 只有发球的真回合 |
