# 反馈驱动修正：流式标注生命周期与斜视回合活动

> 应用内的回合反馈功能已移除；本文只作为斜视回合活动修正的历史记录保留，其中关于反馈面板与 `feedback` 字段的描述不再适用。

## 反馈记录并未丢失

本次检查的导出有 5 条标注，均保存在原项目中，来源是同一分析运行的流式候选。临时候选结束后原 `stream` key 与最终结果 key 不同，卡片入口会重新向已经结束的任务索取上下文；另一个失败路径是保存已经成功、随后刷新失败，表单仍按未保存的临时对象重试。

修正：

- 卡片优先打开已经保存的反馈对象，后续按 ID/revision 修改，不依赖该候选仍存在。
- 流式反馈可与**同一运行 ID、同一视频、同一回合 ID 与精确起止范围**的最终回合显示关联；不改写原始证据，不跨批次、不靠编号关联。
- Go 在打开表单时生成 `context_id`，冻结源快照。任务结束或候选变化后，已打开但还没提交的草稿仍能作为原批次反馈保存；客户端不能伪造/改变该快照，跨视频或过期 token 拒绝。会话内最多 256 份上下文，重启不恢复未保存草稿。
- 写入返回的反馈 ID 先被记住，刷新失败不再退回新建；原子保存和 revision 冲突校验保留。
- 原项目、原始反馈、用户时间轴均不自动改写，反馈不自动标为已解决。

## 算法原因

该素材为斜视 `perspective-rims` 机位，不是已有几何死球规则支持的长侧视图。原算法检测到球后按时间连续性组合，可能把准备、捡球、回送和下一次发球连在一起；音频只能补充证据，不能可靠分辨这些动作。原早段没有任何几何死球事件。

新增共享 `vision/rally_activity.py`（`perspective-activity-v1`）：

- 仅在正常解码已取得可信斜视桌面几何的时段启用辅助分段；无几何、侧视与显式 `legacy` 不套用此规则。
- 需要球员端真实抛球式上升/下降或快速跨桌往返证据启动；一次跨桌回送不直接算下一回合。
- 持续放缓的低位球路，在等待快速恢复后，形成 `ball_settled` 活动边界；真实观测空档形成 `activity_gap` 边界。正常往返、高位慢球不以此直接结束。
- 一次发球失败也能保留为短候选，而不是因为不到 1 秒就丢弃。
- 活动边界保护音频融合和导出缓冲，既有切镜与几何死球边界不被覆盖。参数、权重、RGB 预处理、模型输入和跟踪都没有改变。
- 默认依旧无预校准、无球桌 ROI 检测门限；所有模型检出和轨迹仍保留。这里的桌面走廊只限定回合证据，不删模型点。

这些是**活动分界，不是下网/出界裁判事件**。缺少可信网面时，仍不声称已经认出下网。抛球准备与真实发球可能相似，低慢旋转球和严重遮挡仍可能误分；未经全场人工真值验收不能称为准确率提升。
