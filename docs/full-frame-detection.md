# 整帧检测迁移：球桌不是模型启动门槛

## 当前默认

`table_mode=optional`：从原片第一个真实画面开始解码与模型推理。不前置 `calibrate()`，不等待 600 秒/跳搜。所有热图检出点都进入跟踪，不用旧桌面 ROI 丢弃模型点；轨迹本身仍有最小点数/运动一致性要求，不能将其误称为“保存所有原始检测”。

桌面几何仅在正常解码时采样，成功后辅助桌框与几何规则。前约 9 秒按真实 PTS 稀疏尝试，之后间隔重试；从未成功也是合法结果，不创建 `[0,0,1,1]` 伪球桌。缺几何时不判触网/出界，也不能可靠区分全部捡球/回送，候选需人工复核。

### 显式选择

- `--table-mode optional`：默认，无前置校准；可选几何不阻塞检测。
- `--table-mode off`：不尝试桌面几何，只有全帧检测/跟踪、声音辅助、切镜边界。
- `--table-mode precalibrate`：兼容性的显式旧搜索，可用 `--calibration-seconds` / `--calibration-jump-samples` 调预算。失败警告后仍继续全帧检测，不回退 mock。取消、超时、解码或模型错误仍需报错。

`net_region` 只有在配套可信桌面几何存在时用于规则；切镜后不沿用首镜头手工网面。

## 镜头与并发清理

旧 `Shot` 对象在解码线程中可变，而后处理线程会看到已经提前变化的状态。现已移除 `applied/bound/resolved` 跨线程访问和循环套旧 ROI：

1. 每帧携带冻结的 `ShotSnapshot`，后处理只按源顺序读取该帧的状态。
2. 切镜立即清除几何并结束旧活动轨迹；之前已经足够的短轨迹保留，不连接到新镜头。切镜要求画面整体变化（3×4 网格 ≥80% 的格子平均差 ≥9），有人从固定机位前走过只改变部分画面，不算切镜（见 `side-transit-segmentation.md` v4）。手持晃动、摇镜也不算切镜：候选帧在 128×72 抗混叠灰度图上按相位相关补偿整体平移后，平均差仍须 ≥15（`ALIGNED_CUT`），见 `camera-motion-cuts.md`。镜头移动不切镜时，几何不能沿用过期位置：与取得几何时相比整体平移 >3%（相隔 1 秒连续两次）就按同一平移量移动球桌框和网面，移出画面或平移过大才清除并在同一镜头内重新获取；轨迹和模型三帧输入不断开。
3. 三帧模型输入不能跨镜头；不足三帧的切镜/结尾尾巴不复制填充，`unscored_frames` 如实记录。
4. 新镜头重新尝试可选几何，未得到时继续全帧检测。
5. 回合与音频组合也被镜头边界切开；摄像机切换不是死球，不制造 `dead_ball` 事件。
6. 有效的旧死球边界不删除；几何丢失或切镜时结束该时段的待发球状态，不让未知镜头永久卡在 `WAIT_SERVE`。

旧校准/跳搜实现保留为显式流程；旧颜色启发式 `classical-av-v1` 仍仅用于对照。没有大范围删除用户参考代码。

## 协议 / 保存 / UI

- `summary.table_bounds` 可为空数组、null 或缺省；仍严格拒绝长度错误、越界或倒置矩形。
- `table_segments` 记录实际几何可用时段：未知段 `bounds=[]`，不能将未来找到的 ROI 回填到未确认的早期段。
- `table_mode`、`geometry_available`、`unscored_frames`、`implementation` 记录实际行为；初版为 `full-frame-v1`，斜视活动修正为 `full-frame-v2` + `activity_rule_version=perspective-activity-v1`，见 [反馈修正](feedback-activity-fix.md)。旧项目缺字段按未知处理。
- Go / headless / 项目校验都允许无桌成功结果；轨迹、权重 SHA-256、时间戳、评分和事件证据仍检查。
- 流式 `table_bounds=[]` 必须传到 UI，不能被“空数组不发事件”逻辑吞掉，也不能用旧缓存桌框补回来。省略/null 的旧流式字段表示未更新；新 worker 用明确 `[]` 清除。
- 没有当前桌面几何时禁用桌框开关，不影响轨迹开关；新分析不混用上次结果轨迹/桌框。实时几何只显示在其出现时间之后，历史镜头以完成后的分段信息为准。
- 算法源码摘要变化隔离旧缓存；已保存项目不会自动重切。已有人工编辑继续保护，可显式采用新结果。

## 实际验证

### 原始 0043 整段新鲜推理

原片只读，MPS / FP32 / batch=4。不是保存项目转换，不是只回放旧检测：

- 解码/评分 4,776 帧，原始检测逐帧与改动前比对：**0 帧数值变化**，PTS 一致。
- 每帧进入跟踪的点数等于原始模型检出点数，0 个 ROI 丢点。
- 最终保留 89 条轨迹；旧 ROI 版本 87 条。增加轨迹不是准确率提升证明。
- 可选几何约在 3.003 秒获得；此前正常推理，未做前置搜索。
- 17.924533 秒与 34.340933 秒两处用户报告的结束仍保留，后续发球起点分别 20.4204、36.5365 秒。
- 原始报告 `/tmp/rallycut-full-frame/comparison.json`；原始检测 `/tmp/rallycut-full-frame/0043-predictions.jsonl`。
- `/tmp/rallycut-full-frame/0043-full-frame.rallycut.json` 是旧格式历史回放产物；当前版本不再直接载入，新格式项目需输出为 `*-rallycut.json`。

### 完全无几何的成功管线

- 正式 Go worker 在绿色无桌合成视频上完成 120 帧实际推理，无几何、无伪死球，成功保存 JSON/项目。这是合成协议回归，不是模型准确率证明。
- 仓库外独立 skill 对真实 DJI 短片显式 `--table-mode off`：11 条轨迹 / 2 个候选，`table_bounds=[]`、`geometry_available=false`、无几何死球事件。
- 单测覆盖 ROI 外模型点不丢、默认不调用校准、显式旧校准失败继续、无桌结果与空表框清除、不可变快照、VFR/重复帧、顺序/流水线切镜、禁止跨镜头轨迹/三帧窗口/音频合并。

没有独立全片真值，不宣称回合准确率达到规划指标。没有几何时仍可能连上捡球动作，这是证据不足的明确降级，不应重新引入强制标定门槛来掩盖。
