# 非侧视时段：自校准画面坐标的抛球发球 / 击球分段（`frame-serve-v8`）

## 何时使用

`vision/rally_activity.py` 按时段选规则，证据强的优先：

1. 可信侧视几何（`side-color-rim`）→ `side-transit-v4`（台宽 / 台高为单位）。
2. 其他所有时段（斜视框，不论固定还是随镜头移动；完全没有几何）→ 本规则 `vision/rally_serves.py`，前提是本规则自身的假设成立：球的长单调段 ≥70% 沿画面 x 方向（`horizontal_view`），并且有 ≥40 段球的运动可用于校准。
3. 本规则不能运行（如沿 y 方向打的端线机位）时，斜视框才用 `perspective-activity-v2`；再没有几何就放开，不编造分段。

连续的第 2 类时段合并成一次计算，几何的频繁变化不会切断回合。本规则选出的回合在 `rally_state.resegment` 里也不再用斜视框裁掉“台下”的尾段（本规则本来就不看球桌框；0044 的 03:31 就是这样被整段丢掉的）。v2 的整片门槛（宽高比 ≥3 等）和 v3 的“稳定斜视框 ≥60 s 仍用斜视规则”都已去掉：在第一份固定斜拍真值 0044（前 5:05，33 回合，调参时没用过）上，斜视规则 IoU≥0.5 为 27 / 11 / 6（TP / FP / FN），本规则为 27 / 5 / 6，边界准 42% → 61%。

## 尺度自校准

阈值不再用固定的画面宽度单位。每个视频先统计自己的球：

- W：球的横向单调段位移的 90 分位，大约是画面里一个球台长度。
- S：位移 ≥0.3 W 的长段的速度 75 分位，即典型击球速度。

距离阈值写成 W 的倍数，速度阈值写成 S 的倍数；机位远近、缩放不同，规则不变。时间（间隔、提前量、尾巴）仍是秒：比赛节奏与画面大小无关。画面左右 6% 的边缘仍按画面比例（从画外扔进来的球）。

## 规则

- 击球：横向单调段，位移 ≥0.29 W、速度 ≥0.37 S，起点不在画面边缘。
- 抛球：近乎竖直的段，竖直幅度 ≥0.29 W 且 ≥1.5 倍横向位移（物理尺度比较）。抛球后 2.5 s 内、起点相距 ≤0.29 W 的第一拍可以慢到 0.21 S（透视下的发球）。
- 开始：抛球 + 发球，或单独一拍速度 ≥0.64 S。起点 = 抛球开始前 1.2 s，否则第一拍前 1.0 s。
- 延续：下一拍间隔 ≤1.8 s；慢速推挡 / 断续跟踪（≥0.06 W、≥0.11 S，彼此间隔 ≤0.8 s）可桥接到 3.0 s。间隔 ≥1.0 s 后出现新的抛球 + 发球，开始新回合。
- 结束：最后一拍后 0.8 s，原因 `stroke_gap`（“击球中断”），不是触网 / 出界判定。
- 慢速漂移结束（v5）：最后一拍之后出现持续 ≥1.0 s、速度 <0.33 S 的横向运动（球在滚 / 被拿着走），即视为死球，后续慢速回送不再把下一分连进来；下一分照常需要抛球发球或快速一拍才开始。比赛中的高吊球约 1 s 过台、速度约 0.45 S，不触发。阈值在 0.8–1.2 s、0.25–0.4 S 范围内结果相同（0041 / 0043 / 樊振东不变）。v6：慢速段之后 0.5 s 内紧接一拍快球（≥0.64 S，直接进攻这个慢球）说明球仍在比赛中，不结束。
- 比赛中的高球（v6）：紧接比赛中动作（0.8 s 内）出现的竖直高球（高吊、高挡）延续当前回合，不当成新的抛球发球；新发球的抛球之前要有停顿。
- 发球前颠球（v4）：发球员把球在台上 / 地上颠几下（樊振东从地上颠，用户确认标注范围内 5 处均为颠球）。识别为一串 ≥3 段交替上下的短竖直运动（每段 0.06–0.6 W、横向漂移小、间隔 ≤0.35 s、同一位置）。若它在发球（抛球，否则第一拍）前 8 s 内结束、位于发球方一侧、且在上一回合结束之后，回合从颠球开始（`start_reason=serve_prep`），之后停顿和发球都算同一回合，让观众看到发球前的准备。没看到颠球时仍按抛球前 1.2 s。
- 跟踪跳点：前后都几乎不动、中间一步横跳 ≥0.06 画面宽，是跟踪器把持着 / 颠着的球和别处静止的球连在一起，不是飞行。这一步现在在公共层 `rally_transits.ball_runs`，侧视过台规则也用（0041 / 0043 结果不变）。

不删模型点或轨迹，不用声音。死球事件、切镜边界仍优先。

## 跨视频检验

相对系数由樊振东前 430 s 的 19 个回合换算而来（换算后该段结果与 v2 相同）。为检验能否推广，把同一规则在**不用任何几何**的情况下直接跑在 0041 上（侧视业余固定机位，调参时没用过它），和 0041 的人工标注比：

| 规则跑在 0041（122 个必须识别的回合） | IoU≥0.5 TP / FP / FN | F1 |
|---|---|---:|
| v2 固定画面单位 | 117 / 31 / 5 | 0.87 |
| v3 自校准 | 111 / 14 / 11 | 0.90 |

0041 的 W、S 约为樊振东的 1.3 倍、1.6 倍；不校准时阈值相对过低，回送球被当成击球。这是本规则作为“无几何兜底”在另一个场景的留出检验，它仍明显不如 0041 有几何时的 `side-transit-v4`（122 / 0 / 0），所以有可信侧视几何时仍优先用后者。

- 0044 的回合在加入去掉框裁尾之前，同一轨迹上为 27 / 5 / 6；修复后多找回一个（03:31），也多一个误报。

## v6：樊振东 20:00–30:00 盲测（20 回合）

拿到真值时先用 v5 原样打分（新鲜推理）：IoU≥0.5 为 9 / 10 / 11，IoU≥0.3 为 15 / 4 / 5。结束时间基本准确（多数相差 ±0.5 s），主要问题是起点：
- 这段人工起点从发球准备算起，比检测到的发球晚 1.6–6.6 s（中位约 3.7 s），而准备阶段的球大多没有检测点或幅度太小，靠轨迹找不回来。前 430 s 的人工起点是抛球口径，两段口径不同：统一加 3 s 前置时 20–30 分钟段变成 15 / 3 / 5，前 430 s、0044、0045 都明显变差。所以这部分交给导出的“发球前保留秒数”，不改识别边界。
- 算法错误：两次回合内部被切开，分别是高球被当成新抛球、慢速球后紧接进攻被当成死球，v6 已修，新鲜推理结果为 11 / 6 / 9（IoU≥0.3 为 15 / 2 / 5），0041 / 0043 / 0044 / 0045 / 樊振东前 430 s 的标注范围内不变。还有 4 个漏检，都是检测阶段几乎没有横向击球轨迹；另有 1 个回合被镜头切换检测误切（27:52）。
- 用户确认口径：识别从发球开始即可，看得到颠球时尽量从颠球开始。按此口径（标注里的准备段可选；23:05、27:38 两次发球擦网重发记为可选）v6 为 **16 / 2 / 2**，边界准 83%。剩余漏检：22:39（颠球后发球、接发球下网，只有颠球点、发球和接发球几乎没有检测点）、26:49（真实回合，横向轨迹很短）；误报：20:26 一段、27:52 误切。
- 颠球识别在这段只命中 1 / 18（起点在人工起点 ±1.5 s 内）：准备阶段的球大多没有检测点，或者颠出画面底部。放宽幅度 / 间隔 / 次数最多命中 3 / 18，但 0044 / 0045 会出现比人工抛球口径早的假颠球起点，没有采用。

## 局限

- 只在两个场景上检验（樊振东观众视频、0041 / 0043 同一张球桌）。0044 / 0045 / 奥运片段没有真值。
- 樊振东剩下的差异用户看画面确认都与发球前在台上颠球有关：03:23、06:28 人工起点含颠球，机器从抛球开始（重叠但 IoU<0.5，用户认为可接受）；06:45 颠球后只有慢速断续轨迹，漏检。试过把颠球追溯进起点，但人工起点含不含颠球不统一，结果不升反降，没有加这条规则。
- 稳定斜视框的 60 s 门槛仍来自 0041 / 0044 / 樊振东三个视频。
- 只处理沿画面 x 方向的对打；沿 y 方向（端线机位）的视频放开。

## 软开局（v7）

业余 / 休闲对打常以软发球、搓球开局，前几拍低于按本视频快球校准的击球速度，回合要等到第一拍快球才打开，起点晚 2–3 s。v7：回合打开后，如果紧挨在第一拍之前有一串横向运动（每段 ≥0.15 W、≥0.11 S、间隔 ≤0.8 s）且来回换向 ≥2 次，起点前移到这串的第一段（再减 1 s 前置；若那里能连到抛球则按抛球）。只有一个方向的慢速运动（把球递 / 送回发球方）不算。

证据（`just eval run`，在已核对“重放 = 新鲜推理”的 L0 缓存上重放）：新视频 he（整段 21 回合，加入前从未分析）首次独立成绩 11 / 8 / 10（F1 0.55）；v7 后 15 / 4 / 6（F1 0.75），其余 5 个视频的对上 / 误报 / 漏检不变，边界准：樊振东 76→78%、0044 61→64%、0045 73→81%。换向次数 2 是稳定区：1 次会把 0045 的一次递球连进回合，3 次几乎不起作用；段长 0.1–0.15 W 结果相同。he 此后不再算独立测试。

同时试过“连续 ≥3 拍来回、单拍都不快也开回合”（针对 he 02:18 的软对拉）：he +1，但 0044、0045 各 −1，未采用。

## v8：误报清理与回合不被中途截断

基线 v16 合计 242 / 13 / 13（F1 0.949）→ v8 **244 / 3 / 11（F1 0.972）**，0041 / 0043 不变，没有任何视频变差；每条都做了参数扫描，取结果不变的区间中部（证据均为 `just eval run` 在已核对 L0 缓存上的重放）。

1. **画面规则的回合不被视觉尾段裁剪截断**（`rally_state.resegment`）：画面规则的一个 episode 就是一个回合；`segment_rallies` 的尾段裁剪若在最后一拍（episode 末 − `TAIL`）之前就结束，回合延到 episode 末，多段合成一段。起因：0045 01:16 一分中段 0.4 s 慢速球让裁剪丢掉后面 5 s 对拉。顺带发现：无几何时 `visual._active_flight` 的阈值（0.18 步长、0.35/s）按归一化坐标写，而这里的轨迹是像素坐标，裁剪基本只对近乎静止的抖动点生效；把单位改对（×960）反而 242 / 2 / 13（樊振东、0045 各丢 1 个），未改，由本规则自己的慢速漂移结束负责结束判断。
2. **软开局换向 ≥1 次即可**（`LEAD_REVERSALS=1`，`LEAD_DX=.08`）：软发球 → 第一拍快球的回接本身就是一次换向。之前“1 次会把 0045 的递球连进来”的结论其实是上面截断问题造成的；修好后 1 次在 `LEAD_DX` 0.04–0.12 W 范围结果相同（244 / 11 漏检里 he 找回 2 个），0.2 W 起退回原样。单向搬运不算；把球递回发球员之后要接球、抛球，停顿超过 `WEAK_GAP`，也不会被连上。
3. **抛球必须留在发球员处**（`TOSS_MAX_DX=.4` W）：又高又横移 ≥0.4 W 的球是回合后的挑高 / 弹起，不是抛球（0044 02:12：挑高后慢慢回送被当成“抛球 + 发球”）。0.29–0.5 W 结果相同，0.2 W 会丢真回合。
4. **从画面边缘进来的球不是发球**（`THROWN_IN_GAP=1.5` s）：没看到抛球、且 1.5 s 内有一段从画面边缘进入的球（别处丢 / 打过来），接着击球不开回合（0044 02:34）。0.8–3 s、边缘段 0.1–0.6 W 结果相同；证据只有 1 例，属低证据规则。
5. **孤立一拍不是回合**（`LONE_DX=.12` W）：没看到抛球、也没有颠球，episode 里除这一拍外没有任何 ≥0.12 W 的球运动（没有接发、没有弹跳、没有回球）——回合间把球打回 / 打走。去掉 6 个误报（樊振东 20:26、0044 02:53 / 04:29、0045 01:37 递球、03:10、he 01:33），没有丢真回合；0.06–0.2 W 结果相同。有抛球的单拍保留（发球失误算回合）。

未采用：
- “孤立一拍”改成“没有反方向的运动”：he 再少 1 个误报，但没看到抛球的发球失误（球只朝一个方向）会被删，而用户确认发球失误算回合。
- 没有抛球、只有一拍的 episode 一律删除：误报降到 4，但 0044 / 0045 / he 共丢 11 个真回合（很多真回合只检到一拍快球 + 其他弱运动）。
