# 侧视过台分段（side-transit-v4）

## 问题

侧视（`side-color-rim`）此前只靠 `segment_rallies`：轨迹间隔 ≤ 1.15 秒就算同一段。两分之间捡球、回送、准备发球时球几乎一直可见，相邻两分常被连成一个候选；起点又固定前推 1.6 秒，被前面的回送拉早。几何死球规则（出界、台下停滞、接住、下网）覆盖不到最常见的“没接到、落地、捡回”。

用户在 0041 前 5 分钟人工标注后（去掉两处重复标记，29 分），旧版：TP 13 / FP 12 / FN 16，4 处合并，边界准（起止都 ≤1s）24%。

## 规则

`vision/rally_transits.py`，只在可信侧视几何（`method=side-color-rim` 且归一化宽高比 > 4）时由 `rally_activity.activity_intervals` 启用；斜视仍用 `perspective-activity-v2`，无几何 / 窄框 fail-open 回到原逻辑。

- 每条轨迹按水平单调拆成“过台”片段（时间断开、水平反向、竖直抛起后开始横移都会切开）；v4 另去掉片段开头近乎竖直的一步（横移 <0.05 台宽、竖直 >0.5 台高，即粘在发球前的稀疏抛球点）。特征以台宽 / 台高为单位：横移幅度、水平速度、相对台面的最高点。
- 实测区分：对打过台约 1.2–3.5 台宽/秒、最高点 0.1–1.1 台高；回送约 0.5–0.9 台宽/秒、最高点 1.3–2.9 台高。
- 强过台（≥0.55 台宽、≥1.0 台宽/秒（v4，此前 1.1）、最高点在 −0.5–1.6 台高之间（v4 新增下限）；或 ≥0.3 台宽、≥1.4 台宽/秒、≤1.0 台高）才能开始一段，但最高点 >1.0 台高且 <1.5 台宽/秒的强过台（v2：球拍把球轻送回发球方）只能延续、不能开始；弱过台（如高吊防守）只能在 0.5 秒内延续。强过台间隔 ≤1.2 秒延续（v1 为 0.9 秒）。
- 起点（v3）：取“第一次强过台前 1.3 秒”与“其前 2.5 秒内球台一端竖直抛球起点减 0.2 秒”中较早者（v1/v2：有抛球用抛球，否则前 1.0 秒）。只有一次强过台的段，该过台最高点须 ≤0.8 台高（发球），否则视为送球丢弃。终点：最后一次过台后 0.5 秒，原因 `transit_gap`（UI：“过台对打中断”）。尚未观测满 0.9 秒的末段不给结束原因。
- 只发一拍就失误的分保留；分析走廊（台宽 ±0.35、台面上 3 台高 / 下 1.5 台高）外的运动不计。完全不用声音。
- `BallValidity` 的几何死球事件、`serve_restart`、切镜边界照旧优先并保留；切镜后无几何的片段开头标 `camera_cut`。
- `transit_gap` 只是过台对打中断，不是触网 / 出界判定。不删模型点或轨迹。

版本：`implementation=full-frame-v7`，`activity_rule_version=perspective-activity-v2+side-transit-v4`（v3 为 `full-frame-v6`，v2 为 `full-frame-v5`，v1 为 `full-frame-v4` / `side-transit-v1`，下面第一张 A/B 表是 v1 相对旧版）。

## v2 调整（同一批新鲜轨迹）

## 公共跳点过滤

`ball_runs` 在切单调段之前先去掉跟踪跳点（前后几乎不动、中间一步横跳 ≥0.06 画面宽：跟踪器把持着的球和别处静止的球连在一起）。它和 `frame-serve` 共用；在 0041、0043 的同一轨迹上回放，结果与之前逐项一致。
