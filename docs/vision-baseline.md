# 真实画面实验基线：classical-av-v1

这是替代 `mock-v1` 的第一条真实分析路线，**不是已经验收的自动回合识别产品**。该基线不使用下载的神经网络权重。

## 实际做什么

1. OpenCV / FFmpeg 后端解码每一帧，以解码器的 `CAP_PROP_POS_MSEC` 作为时间轴，不按 `frame_index / 30` 推算。
2. 在真实画面中定位蓝色 / 紫色球桌，限制运动候选区域；不支持的球桌或无法读取的文件明确报错。
3. 使用帧差、亮度背景残差、局部形态学、颜色与连通域几何提取运动小球候选。
4. 基于位置 / 速度预测关联短轨迹，并检查横向运动范围、过台区域和短时轨迹拟合误差。它们仍是**候选轨迹**，不是已确认的球位置真值。
5. 按实际轨迹的观测间隔生成视觉候选；有音轨时由 Go 调用 FFmpeg 提取临时单声道 PCM，Python 用分块 FFT 提取高频声音瞬态。
6. 只有与视觉短轨迹重叠的声音序列才参与补足遮挡与回合边界，**不生成仅有音频证据的回合**。
7. 输出真实时间戳、归一化坐标、候选回合和分析摘要。UI 可独立打开“显示球轨迹”与“显示球桌”核对，不再只展示无法验证的分段数字。

缺少 OpenCV / NumPy、解码失败、时间戳无效会使任务失败；没有足够证据则返回空列表。任何情况下都不会回退到固定时间窗口模拟分析。

## 环境与复现

```bash
just setup  # uv 创建 Python 3.12 venv，安装固定版本 OpenCV / NumPy
wails dev

# 不启动 GUI，使用与桌面完全相同的 Go → Python 正式管线
# 输出使用新文件名，不要覆盖已有项目
go run ./cmd/analyze \
  -input '/absolute/path/match.mp4' \
  -output '/tmp/match-analysis.json' \
  -project '/tmp/20261024-152433-rallycut.json'
```

桌面程序优先使用 `RALLYCUT_PYTHON3`，其次查找 app 本地 `venv`、项目 `.venv`；从 `build/bin/RallyCut.app` 启动时可沿可执行文件父目录找到项目环境。安装到 `/Applications` 后应另外准备运行时或设置明确的 Python 路径，尚未制作自包含分发包。

## DJI 素材的开发检查

使用用户提供的 DJI HEVC 1080p / 29.97fps 视频前 180 秒进行开发排错，**这段素材参与了阈值选择，不能作为独立测试集计算准确率**。

已实际发现并处理的问题：

- 开头遮挡和墙面导致初版球桌定位过宽：收紧紫蓝色范围，并约束长宽比和位置。
- 球网的高频纹理 / 压缩闪烁产生伪轨迹：加入背景亮度残差，不能只使用帧差。
- 抽帧容易漏掉横跨球桌的高速球：改为逐帧分析。
- 单靠视觉轨迹会产生碎片 / 漏回合：加入击球声瞬态辅助，但仍要求真实视觉证据。

当前开发检查的前 180 秒产生 58 条候选短轨迹；联合 172 个声音瞬态产生 16 个候选回合。**这些数字只说明实际分析输出，不代表 16 个正确回合，也不是召回率。** 视觉-only 与联合路线的回合数不同，背景动作仍可能误判。

## 当前限制

- 只针对固定机位蓝 / 紫球桌，绿色球桌、移动机位、多球训练暂不支持。
- 使用缩放后 960px 宽画面，极小球、模糊、遮挡会漏检。白衣、反光、手部和邻桌球仍可能误检。
- 音频无法可靠区分脚步、球拍击球、落台与说话，且未在非零音视频起始偏移素材上验收。
- 连续练球或很短的局间停顿可能被合并，长时间漏球也可能把同一回合切碎。
- `confidence` 是启发式证据强度，不是神经网络概率，更不等于回合准确率；`score` 是时长 / 轨迹和瞬态密度的粗排分数。
- 没有人工真值就不能报告精确率、召回率或 ±1s 边界达标率。
- 当前缓存为整次任务级别，不能逐帧断点续跑。缓存键包含源文件 SHA-256、协议、算法 ID 和内嵌算法源代码摘要，修改实现不会命中旧模拟 / 旧算法缓存。

## 原项目如何迁移

重新分析时机器回合按新结果替换，人工添加 / 修正的回合保留（规则见 `docs/protocol.md`）。空时间轴（包括人工删空）自动采用机器候选。原始候选 / 轨迹始终与编辑时间轴分离。

## 下一步验收，不再以“能跑”代替效果

1. 人工标注这段视频的每分起止时间，记录漏回合、误检和边界偏差。
2. 在独立视频上复核，保留白衣 / 球网 / 捡球等固定难例。
3. 核实可合法部署的预训练球检测权重与许可证，接入更可靠的 TrackNet / 专用球检测器，对比此传统视觉基线。
4. 模型接入后继续沿用同一轨迹协议与人工编辑机制，不再动 UI 去掩盖算法质量。
